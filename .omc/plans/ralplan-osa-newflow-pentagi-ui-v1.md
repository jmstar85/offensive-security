## RALPLAN-DR Summary

### Principles
1. **Additive seam, never rip-and-replace.** Every new routing/mode path is gated and falls back to the exact current behavior when its flag/field is absent. The **byte-identical W0 replay guarantee rests on the `service.py:315` lane gate** (`lane == "fresh_plan"`): the saved-workflow / no-LLM demo lane **never enters `_run_autonomous_lane`** and reads the new columns only as server defaults. It does **not** rest on an empty `model_map` yielding `None`→smoke (that claim is corrected — see Principle 9).
2. **One sanctioned dispatch site.** Assistant and Automation both reach dockerd only through `Performer._dispatch_tool` → `execute_tool_through_safety_chain` (performer.py:265-479). No second execution path and **no new reachable role** is introduced; the AST/adapter-execute guards stay authoritative.
3. **One sanctioned execution launcher.** Both the legacy `/sessions/` path (Path A) and the redesigned `/pentest-sessions/` path (Path B) reach the autonomous engine through **one** launcher (`launch_autonomous_execution`), so per-role routing and the PM1 credential-context wrap are applied at a **single, provably-covered** site rather than one of two divergent subsystems. Path B's `approve` schedules that launcher; there is no second unwrapped `async_session()` spawn.
4. **The full safety chain is structural, not partial.** "Same safety chain" means: the **shared session-start target-scope whitelist gate** (`validate_session_target`, extracted to a shared callable so both `OrchestratorService.run` and `AssistantService.turn` call it once, identically), the per-dispatch tier/exploit/risk filter trio, the **runtime `EgressMonitor` as the per-call scope brake** (identical to Automation — there is no per-call pre-flight target gate on either lane), **and** the ADR-003 concurrency lease — all proven by spy, not asserted by analogy. Because the ADR-003 `_PerformerLease` is keyed by *session identity* (not per-turn), interactive turns are **serialized per session** so the lease's per-session semantics stay correct (Principle 4a).
   - **4a — Per-session turn serialization.** `_PerformerLease` is a module-global set keyed by `session_id` (performer.py:54,608-631): `__aenter__` `.add`, `__aexit__` `.discard`. Two concurrent turns on one `session_id` would collapse to one set entry and the first `__aexit__` would release the shared lease while the second turn is still dispatching. Interactive mode structurally invites this overlap. Therefore the Assistant endpoint holds a **per-session turn mutex**: a second turn on a session with a turn in-flight is refused (409) rather than run concurrently. This makes "one live turn per session" true, so the per-session lease is correctly scoped.
5. **Credential isolation is contextvar-scoped, explicit-arg-first, and UUID-typed.** Every LLM client is minted per role via `LLMRouter.route`, passed `user_id` **explicitly** as a normalized `uuid.UUID` (the real isolation guarantee), with `with_user_context` as belt-and-suspenders — no client cached across users, no key threaded as a plain argument, no `str`/`UUID` mismatch silently matching zero rows.
6. **Session/engine execution default ≠ internal-role fallback default ≠ interview/chat default.** Three distinct defaults, decoupled: (a) the user-facing **session/engine** default `claude-opus-4-8` (consumed by `ModelSelector`/`session.model_id`, used to route the autonomous engine roles); (b) the cheaper **internal-role fallback** `claude-sonnet-4-6` that `resolve_role_llm_model`/`resolve_role_send_model` read (unchanged); (c) the **Coordinator interview/chat** default, resolved **PER-PROVIDER from `session.llm_provider_pref`** to a cheap-per-provider model — NOT a hardcoded Anthropic id (Blocking 1, iteration-5 Critic). It is **not** silently promoted to opus by `session.model_id`.
   - **6c — Per-provider interview/chat model (Blocking 1).** The interview MODEL must be coherent with the interview PROVIDER, or "Ollama never prompts" (immutable constraint / AC#15 / Principle 2) breaks: pinning the model to the Anthropic id `claude-sonnet-4-6` while the provider is `ollama` sends `OllamaClient.send(model_id="claude-sonnet-4-6")` (a garbage id to Ollama), and forcing `provider=anthropic` for coherence would fire the `AddCredentialModal` on an Ollama-only session. Fix: a single resolver `resolve_interview_model(session)` maps `session.llm_provider_pref` → cheap default: **`anthropic → claude-sonnet-4-6`** (today's behavior preserved), **`ollama → qwen3-14b-96k:latest`**, **`openai → a cheap gpt id`** (e.g. `gpt-4o-mini`). When `llm_provider_pref` is **NULL** it falls back to `settings.osa_llm_provider`'s cheap default (anthropic ⇒ sonnet-4-6), so legacy interview behavior is byte-identical. The provider itself is always taken from `session.llm_provider_pref` (single field, Finding 6), so an Ollama-only session completes the pre-execution interview/chat with **zero credential prompts** and **never sends an Anthropic model id to `OllamaClient`**.
7. **Fail-closed on tiers, providers, and missing credentials — never fail-open to fabricated findings.** Unknown provider/model, missing credential, or an unset tier flag **drops or hard-fails** the step/turn rather than degrading to a broader capability **or to a fabricated smoke fixture**. On the bound live lane (`performer.state.egress_monitor is not None`), a missing credential MUST raise `CredentialNotFound` — the `if client is None: return self._smoke_result()` branch (pentester.py:105-107, generator.py:88-90, adviser.py:66-67) MUST be unreachable there, so a live pentest can never emit a canned `nmap 127.0.0.1` finding in place of a real one.
8. **The default must be usable — and its fail-closed edges are documented.** The opus-4-8 session default cannot depend on an admin gate; a non-admin session that selects the default must be creatable. Once `osa_multi_provider_llm` is ON (PR9), the `settings.anthropic_api_key` global fallback is disabled (credential_resolver.py:61-63), so with **no stored Anthropic credential**: (i) a fresh-plan default engine run hard-fails `CredentialNotFound`, **and** (ii) — because the flag-ON branch already routes the Coordinator interview/chat through `LLMRouter.route(user_id=…)` (workflow_service.py:331-341) — **interview/chat also now requires a per-user credential**, not only the fresh-plan run. Both are the intended fail-closed, surfaced by the pre-create auth popup and recorded in the risk table.
9. **Name behavior honestly.** The fresh-plan lane with an **empty** `model_map` and an **explicitly-chosen provider** resolves each consuming role against `session.model_id` (opus-4-8, anthropic) → a **real `AnthropicProvider` client**, not `None`→smoke. This is **new behavior**, tested as such — not "byte-identical." Byte-identical is a property of the *saved-workflow* lane only (Principle 1).
10. **The global `osa_llm_provider` switch is PRESERVED, not retired (Finding 5).** Per-role resolution reads the **single** provider field `session.llm_provider_pref` (existing JSONB, session.py:69). When that field is **NULL** (every legacy Path-A fresh-plan session, which the new selector never touched), resolution **falls back to `settings.osa_llm_provider`** and the provider's configured default model — the *exact current `resolve_role_client` behavior* the proven scanme→nmap Ollama E2E rides on. Only when the field is explicitly set (by the Path-B selector) does per-session provider override the global switch. The autonomous lane's behavior for existing callers is therefore unchanged; the E2E stays green with zero migration to those sessions.
11. **One provider field, one interview user-id set-site (Finding 6).** There is **no new `provider` column**; the selector, per-role resolution, and the flag-ON Coordinator interview/chat all read the **existing** `session.llm_provider_pref`. Because `PentestSession` has no `actor_id` attribute, the interview's user identity comes from the `CURRENT_USER_ID` contextvar, which the `send_message`/interview HTTP entrypoint sets explicitly via `with_user_context(uuid.UUID(actor_id))`; this is the set-site the PR9 fail-closed interview test depends on.

### Decision Drivers (top 3)
1. **No new safety bypass and no new reachable path — inbound OR outbound** — Assistant must structurally reuse the *entire* safety envelope through the one dispatch chokepoint **without adding a registered role** a chain role could invoke (inbound), **and without letting the operator-driven loop invoke any `ROLE_REGISTRY` role as a sub-role through `delegate_tool_call`** (outbound), and without extracting/mutating Pentester's proven loop (spec §Constraints, area 1).
2. **No cross-tenant credential leak under concurrency, on the launcher that actually runs the page** — per-role client resolution must thread a UUID-typed `CURRENT_USER_ID` and pass `user_id` explicitly into `route`, applied at the **single** launcher both session paths use, with the launcher matching `OrchestratorService.run`'s real signature (area 2, PM1).
3. **Byte-identical replay + AST guard + proven Ollama E2E stay green** — additive gating is mandatory; the routing change must be provably a no-op on the *saved-workflow* lane via the `service.py:315` gate **and** a no-op on existing Path-A fresh-plan sessions via the preserved global-switch fallback (Principle 10).

### Viable Options

**(a) Per-role provider routing mechanism**

- **Option A1b (revised — RECOMMENDED) — Resolve per-role clients per-invocation via a `user_id`-bound `client_factory` passed as an EXPLICIT `role.run(...)` argument, injected at the two role-launch chokepoints.** The two — and only two — places a role is launched are (i) `run_session`'s **higher-order `reflector_wrap(role.run, performer=self, context=self.state.context, client_factory=…)` wrapper** (performer.py:187-189) — **not a bare `role.run`** — which forwards `**kwargs` uniformly to **every** role in `ROLE_TOPOLOGICAL_ORDER` (`['generator','pentester','reporter']`), including non-consuming roles like `reporter`, via `reflector.wrap`'s `*args/**kwargs` passthrough (reflector.py:36-56); and (ii) `delegate_tool_call`'s `ROLE_REGISTRY` branch `role.run(performer=performer, context=payload, client_factory=…)` (runtime_delegator.py:46-49). Both already pass the **same `performer`** object. Because the launch site forwards `client_factory` to **all** roles uniformly, `base.Role.run` and **every** override must **accept** the kwarg (consuming roles use it, non-consuming roles accept-and-ignore — see the signature contract in the Architecture section). `_run_autonomous_lane` stores only the **session-constant inputs** `performer.state.context["role_client_inputs"] = {"db": db, "session": session, "actor_id": actor_id}` **once** (no minted clients live in context) and builds one `client_factory` bound to those inputs; because sub-roles receive that same `performer`, they get the identical factory by construction.
  - **Improvement 3 (adopted) — explicit `client_factory` arg over implicit context threading.** The primary mechanism is `role.run(performer=performer, context=…, client_factory=client_factory)` where `client_factory` is a `user_id`-bound callable (Principle 5, explicit-arg-first). Passing it explicitly — rather than threading routing inputs implicitly through `performer.state.context` (which already carries `_publish_bucket`, `{role}_output`, `objective`) — **removes the need for the read-site AST guard and the delegator assertion for roles that take the arg.** The performer-keyed `role_client_inputs` remains only as the source the launcher/delegator uses to construct the factory, never as a per-role read-site convention. Because the primary launch site is the **uniform** `reflector_wrap(role.run, …, client_factory=…)` forwarder (performer.py:187-189), the kwarg reaches **every** role — consuming and non-consuming — so `base.Role.run` and all overrides (`pentester`/`generator`/`adviser` consume; `reporter`/`reflector`/`memorist`/`seed_xbow` accept-and-ignore) must carry `client_factory=None` in their signature (round-6 blocking fix — see Architecture: Per-role model resolution).
  - **Blocking 2 (applied) — resolve per-invocation, NEVER cache the minted client for the session.** `client_factory(role_name)` calls `resolve_session_role_client(db, session, role_name, user_id=actor_id)` **on every invocation** so `LLMRouter.route`'s advertised contract (router.py:43-45: "each call to route() issues a fresh DB lookup so a revoked-then-recreated credential is picked up immediately … without any cache invalidation step") is preserved: a **mid-session credential revoke is honored on the next role invocation**, and `last_used_at`/the credential-touch audit is written on **every** resolve. Only the session-constant inputs (`db`/`session`/`actor_id`) are performer-keyed; **no `_resolved_role_clients` whole-session client cache exists.** (If any cache is ever introduced it MUST be scoped to a single turn, not the session.) The factory **propagates `CredentialNotFound`** (never swallows to `None`).
  - **Blocking 3 (applied) — explicit `raise`, not `assert`, at the delegator chokepoint.** The `delegate_tool_call` `ROLE_REGISTRY` branch guarantees sub-role resolvability with an explicit `if client_factory is None (or role_client_inputs is None): raise RuntimeError(...)` — **NOT `assert`** — because `python -O` strips asserts, which in any optimized production start would silently revert the guarantee to the exact distributed-convention failure mode this plan eliminates. The read-site AST guard covers **read-sites only**, so this **runtime raise is required** at the chokepoint. This mirrors how `_dispatch_tool` is the single trusted safety chokepoint.
  - `LLMRouter.get_client` gains an `ollama` branch (`api_key: str = ""` default); `LLMRouter.route` short-circuits `ollama` before `resolve_provider_credential`.
  - **A build-time AST guard** (`test_role_uses_role_send_client.py`) fails when any `ROLE_REGISTRY` consuming role (i) reads its client from `context.get("model_client")`/the `context` parameter, or (ii) reads `role_client_inputs` from the `context` parameter instead of via the injected `client_factory`. Non-consuming roles (`reporter`) must not call it.
  - Pros: **per-role routing is correct by construction for top-level AND sub-role-invoked roles** (Adviser, Memorist) because they share the same `performer`/factory; single-slot collapse is structurally impossible (each role passes its own `self.name`); per-invocation resolution → **immediate-revocation + audit-every-touch preserved** (Blocking 2); `user_id` is passed **explicitly** as a UUID; Ollama is first-class; the explicit `client_factory` arg (Improvement 3) removes the read-site convention and the optimized-build assert hole. `run_session`'s dispatch semantics are unchanged (it already passes `performer`).
  - Cons: `LLMRouter.route` gains a provider-specific credential-optional branch; `role.run` signatures gain a `client_factory` keyword; one explicit `raise` guard is added to the delegator role-launch branch.
- **Option A1 (prior) — read helper keyed on the `context`/`payload` argument. Rejected (Finding 1).** `role_send_client(context, role_name)` reading `context["role_client_inputs"]` works for top-level roles but **structurally cannot** resolve sub-role-invoked roles: `delegate_tool_call` passes `context=payload` (runtime_delegator.py:49), and the Adviser payload (pentester.py:241-246) has no `role_client_inputs` key, so the helper either raises or silently falls back to the caller-injected `context["model_client"]` — the exact shared-client anti-pattern A2 was rejected for. Keying on `performer.state.context` (A1b) is the fix.
- **Option A2 — Eager `context["role_clients"]` dict resolved up-front. Rejected** — shared-mutable-context anti-pattern that produced the iteration-1 single-slot bug and the iteration-2 `generator.py` gap; eager resolution decrypts keys + bumps `last_used_at` + writes credential-touch audits for **non-consuming** roles, degrading audit fidelity.
- **Option A3 — Extend the global `resolve_role_client` switch with per-role branches. Rejected** — leaves the credentialed and Ollama paths bifurcated; per-role Anthropic routing still would not thread per-user credentials, failing PM1.

> **Read-site contract (documented + AST-enforced).** Every chain role that emits model output MUST obtain its client via the injected `client_factory(self.name)` (which internally calls `resolve_session_role_client(..., user_id=actor_id)` **per invocation** — no session-lived client cache, Blocking 2 — and **propagates `CredentialNotFound`**); it must **never** read a client or routing inputs from the `context`/`payload` parameter. Roles that produce no model output (`reporter`) must **not** call it. PR6 updates **all** current consuming read-sites — `pentester.py:105`, `generator.py:88`, `adviser.py:66` — to take `client_factory` as an explicit `role.run(...)` arg (Improvement 3) and adds the AST guard. **Signature contract (uniform-forwarding consequence, round-6 blocking fix):** because the launch site forwards `client_factory` to **every** role, `base.Role.run` (base.py:44) **and every override** — the consuming `pentester.py:93`/`generator.py:66`/`adviser.py:51` **and** the non-consuming `memorist.py:80`/`reporter.py:42`/`reflector.py:95`/`seed_xbow.py:92,105,129` — must **accept** `client_factory=None`; consuming roles use it, non-consuming roles **accept-and-ignore**. The AST guard is therefore extended to assert **every `ROLE_REGISTRY` role's `run` ACCEPTS `client_factory`** (accept-and-ignore is otherwise unguarded) **— and that the abstract `base.Role.run` itself carries `client_factory=None`, so a future role that subclasses without the fixed parent still fails closed at build time —** in addition to forbidding client/routing-input reads from the `context`/`payload` parameter. The delegator role-launch branch enforces factory presence with an explicit `raise` (Blocking 3), not `assert`.

**(b) Assistant transport**

- **Option B1′ (revised — RECOMMENDED) — `AssistantService.turn` writes its OWN thin role-free loop over `delegate_tool_call`, with outbound role-invocation containment pushed into `delegate_tool_call` itself as default-deny; Pentester is left byte-identical.** A new endpoint `POST /pentest-sessions/{id}/assistant/messages` (guarded by the per-session turn mutex, Principle 4a) appends the operator turn to the Assistant `MsgChain`, constructs a bound `Performer` (`bind_live_execution`, performer.py:116-141), runs the **shared `validate_session_target` scope gate once**, and drives **one** Assistant turn as a thin loop **inside `Performer._concurrency_guard()`**: prompt the resolved Assistant client → **parse the tool-call envelope via the single-sourced pure parser (Improvement 1)** → dispatch only slugs in `list_agent_types()` → `delegate_tool_call(performer, slug, payload)` → `Performer._dispatch_tool`. The Assistant is **NOT `register_role`'d** (`assistant ∉ ROLE_REGISTRY`, closing the inbound hole) **and** its loop cannot invoke any registered role as a sub-role (closing the outbound hole, Finding 3). `pentester.py:122-247` control flow is **NOT extracted or modified** (see Improvement 1 for the one mechanical parse-call swap).
  - **Improvement 1 (adopted) — single-source the PURE tool-call parser/envelope-validator.** B1′ correctly refuses to extract Pentester's dense/high-risk control flow, but hand-writing a **second** envelope parser for the more-adversarial operator-chat path duplicates injection-hardening surface. Fix: extract **only the pure `parse_tool_envelope(text) -> ToolCall | None` + validator** into a shared module (`backend/app/orchestrator/tool_envelope.py`) that **both** Pentester's loop and `AssistantService.turn` call. Pentester's control flow stays byte-identical (its existing parse expression is mechanically swapped to call the shared pure function, producing identical results — covered by the Pentester byte-identical tests); future injection-hardening of the extractor is inherited by both loops for free.
  - **Improvement 2 (adopted) — outbound containment is a `delegate_tool_call` chokepoint property (default-deny), not an `AssistantService` caller convention.** `delegate_tool_call` has a dual identity — dispatch router *and* role-invocation router (runtime_delegator.py:46-49). Rather than relying on `AssistantService` to filter slugs (a convention any future caller could forget/reopen), `delegate_tool_call` gains an **`allow_role_invocation: bool = False`** parameter: the `ROLE_REGISTRY` role-invocation branch is only reachable when a caller explicitly sets `allow_role_invocation=True`, which **only the trusted automation launcher does**. `AssistantService` calls it with the default `False`, so an operator-emitted `{"tool":"pentester"}` / `{"tool":"adviser"}` / `{"tool":"memorist"}` can **never** launch that role as a sub-role — containment holds by construction for every current and future untrusted caller. **Disjoint-namespace test (Improvement 2):** because `delegate_tool_call` checks `list_agent_types()` **first**, a slug that collided between `list_agent_types()` and `ROLE_REGISTRY` would route to the adapter path and bypass the role-reject; a test asserts the two namespaces are **disjoint** so no such collision exists.
  - **Recursion/cost cap:** in addition to the per-turn mutex (which only serializes turns), the loop enforces an explicit **sub-invocation/step cap per turn**; the bound `Performer` also carries a **sub-role-depth counter** so any nested role launch through `delegate_tool_call` (only reachable on the automation lane, `allow_role_invocation=True`) is bounded, independent of the per-session lease.
  - Pros: **structurally reuses the one sanctioned dispatch and the full safety envelope** — shared session-start scope gate + tier/exploit/risk trio + runtime `EgressMonitor` + concurrency lease — **without adding a new reachable path (inbound or outbound) and without mutating Pentester's proven control flow.** Outbound containment and envelope-parse are both chokepoint properties, not caller conventions. Reuses `msgchains` persistence and WS topics.
  - Cons: a small amount of dispatch glue is written fresh in `AssistantService`; `delegate_tool_call` gains one boolean parameter — a deliberate trade to make containment a chokepoint property and keep Pentester's loop untouched.
- **Option B1 (prior) — Extract pentester.py:122-247 verbatim into a shared `_tool_loop.py`. Rejected.** Mutates the single most safety-critical, most-tested role's proven path for zero safety gain; B1′ reuses only the chokepoint.
- **Option B2 — Register `Assistant` as a Role and drive it via `role.run`. Rejected** — creates a new ungated inbound reachable path (any chain role could emit `{"tool":"assistant"}`).
- **Option B3 — Separate lightweight chat channel with its own tool executor. Rejected** — a parallel executor is the "new bypass" the constraints forbid.

Dominant options (A1b + B1′) are chosen; A1/A2/A3/B1/B2/B3 invalidated above.

**Tradeoff re-price (Improvement 2).** Iteration 4 optimized monotonically for "minimize blast radius on the most-tested paths," which *manufactured* the routing hole (Finding 1) and the outbound Assistant hole (Finding 3). This revision re-prices the axis: **routing correctness and operator-loop containment at the two real role-launch chokepoints** cost a two-line delegator assertion plus one allowlist check — negligible Automation risk — and buy back both correctness holes by construction. The chokepoint move (A1b) is adopted, not deferred; Pentester extraction (B1) remains rejected because its blast radius is real and buys nothing.

## Pre-mortem (exactly 3 failure scenarios)

1. **PM1 — Cross-tenant credential leak, per-role routing dead on the actual page, or the launcher won't run because its signature is wrong.**
   - *Trigger A (leak):* the launcher runs the Performer in a fresh `async_session()` **without setting `CURRENT_USER_ID`**, or passes `user_id=None`/`str(actor_id)` into `route`; under concurrency `resolve_provider_credential` (credential_resolver.py:37) reads a stale/unset contextvar, or a `str` `user_id` compares against the UUID column (credential_resolver.py:43) matching zero rows or the wrong row.
   - *Trigger B (dead code / wrong launcher — FLAG 1):* Path A (`sessions.py:92-113`) is the only current launcher of `_run_autonomous_lane`; Path B's `WorkflowService.approve` (workflow_service.py:529-579) sets `status="approved"` + `plan_json` but **never launches** `OrchestratorService.run`. If PR6's routing/PM1 wrap land only on Path A, they are dead code on the spec's page.
   - *Trigger C (launcher signature — Finding 4):* `OrchestratorService.run` is `async def run(self, session_id: uuid.UUID, prompt: str, actor_id: uuid.UUID)` (service.py:53-54), loads the session itself (:64-67), and seeds `context["objective"] = prompt` (:117, :399). A launcher calling `svc.run(session, actor_id=str(actor_id))` passes a session **object** not `session_id`, **omits `prompt`**, and mistypes `actor_id`; a Path-B objective-only session then has an empty objective and the Pentester "has no task" (pentester.py:136-142).
   - *Consequence:* User A uses User B's credential; **or** per-role routing/credential-scoping never runs for `/pentest-sessions/new`; **or** the PM1 seam raises/no-ops at runtime.

  3. Build a **bound** `Performer` (`bind_live_execution(target, approval_flags=session.approval_flags, whitelist_rules, actor_id)`, performer.py:116-141) so `_dispatch_tool` runs the per-dispatch tier gate (341-355) and seeds the runtime `EgressMonitor`.
  4. Run the **shared `validate_session_target`** gate once before the first dispatch.
  5. Resolve the Assistant client via `resolve_session_role_client(db, session, "assistant", user_id=actor_id)` (explicit UUID) — **resolved per turn, not cached for the session (Blocking 2)**, so a mid-session revoke is honored and `last_used_at`/audit is written. **Missing credential raises `CredentialNotFound`** — no smoke on this bound live lane.
  6. **Run exactly one turn as a thin role-free loop wrapped in `Performer._concurrency_guard()`** (PM2-C): prompt the client, parse the envelope via the **single-sourced `parse_tool_envelope`** (Improvement 1), dispatch via `delegate_tool_call(..., allow_role_invocation=False)` (Improvement 2 — the chokepoint refuses any `ROLE_REGISTRY` slug), honoring the step/depth caps. `run_session` is not used. Stream via `event_bus`; persist the assistant turn + any `AgentExecution` rows.
- **Tier gates**: recon auto-runs; active_recon/active_exploit require `session.approval_flags` — enforced by the same `filter_by_tier_flags` (performer.py:347). No Assistant-specific gate.
- **Mode persisted + fixed**: `session.mode` set at create, never mutated; the endpoint refuses turns when `mode != assistant`.

## ADR

**ADR-NEWFLOW-001 — Per-role LLM routing mechanism and Assistant transport for the Pentagi-style new-flow page.**

**Decision.**
1. **Per-role routing mechanism:** reuse the **existing single provider field `session.llm_provider_pref`** plus a **per-role resolver** (`resolve_session_role_client`) that resolves clients **per invocation** via a `user_id`-bound `client_factory` passed as an **explicit `role.run(...)` argument**; extend `LLMRouter` with a key-less `ollama` branch. (Option A1b + Finding-5/6 refinements.) **Rejected:** adding a new `provider` column / new field, and extending the global `resolve_role_client` switch with per-role branches.
2. **Interview/chat model:** resolve **per-provider** from `session.llm_provider_pref` (`resolve_interview_model`), NOT a hardcoded Anthropic id. (Blocking 1.)
3. **Assistant transport:** reuse `msgchains` + WebSocket and add a new **`AssistantService`** that wraps the already-role-free chokepoint `delegate_tool_call → Performer._dispatch_tool`, driving its own thin loop over the single-sourced `parse_tool_envelope`, with outbound containment as a **`delegate_tool_call` default-deny (`allow_role_invocation=False`)** chokepoint property. (Option B1′ + Improvements 1/2.) **Rejected:** extending `LLMRouter` into an Ollama-agnostic router that hides provider, extracting Pentester's loop into a shared `_tool_loop`, registering `Assistant` as a role, and a separate chat channel with its own executor.

**Drivers.**
- No new safety bypass and **no new reachable path — inbound OR outbound** — through the one sanctioned dispatch chokepoint.
- No cross-tenant credential leak under concurrency, applied at the **single** launcher both session paths use (matching `svc.run(session_id, prompt, actor_id)` exactly).
- Byte-identical saved-workflow replay + AST guards + the proven Ollama scanme→nmap E2E stay green (additive, gated).
- Credential-security invariants preserved: **audit every touch / immediate revocation** (no session-lived client cache), Fernet at-rest, per-user isolation, explicit-UUID `user_id`.
- The immutable "Ollama never prompts" constraint holds on the Ollama-first path the plan markets.

**Alternatives considered.**
- *Routing:* new `provider` column / new field (A3 / two-field) — rejected: bifurcates credentialed + Ollama paths, fails PM1, and duplicates the provider field; extend the global switch — rejected: leaves per-user credential threading unsolved.
- *Interview model:* pin to `claude-sonnet-4-6` globally — rejected (Blocking 1): sends an Anthropic id to `OllamaClient` or forces a credential popup on an Ollama session.
- *Client lifetime:* cache the minted per-role client for the whole session — rejected (Blocking 2): defeats `LLMRouter.route`'s fresh-lookup/immediate-revocation contract and audit-every-touch.
- *Delegator guard:* `assert role_client_inputs present` — rejected (Blocking 3): stripped under `python -O`, reverting to the distributed-convention failure mode.
- *Assistant:* extract Pentester's loop (B1) — rejected: enlarges the most-tested path's blast radius for zero safety gain; register Assistant as a role (B2) / separate channel (B3) — rejected: new reachable/bypass paths.

**Why chosen.** A1b + B1′ (with the three blocking fixes and four improvements) reuse the *entire* existing safety envelope and credential subsystem through **one** dispatch chokepoint and **one** launcher, add routing/containment as **chokepoint properties** rather than distributed conventions, keep Pentester's proven control flow byte-identical, and preserve every immutable invariant (replay, AST guards, Ollama-never-prompts, audit-every-touch) — at the cost of a small amount of `AssistantService` glue, one `delegate_tool_call` boolean, a `client_factory` keyword on `role.run`, and one explicit delegator `raise`.

**Consequences.**
- New migration `012` (additive columns `model_map`, `mode`, `objective`; `llm_provider_pref` reused).
- `role.run` signatures gain `client_factory`; `delegate_tool_call` gains `allow_role_invocation`.
- **Tradeoff (round-6 Improvement 3).** Improvement 3 does **not** eliminate a distributed convention so much as **swap** a runtime *context-key* convention (AST-guard-covered on read-sites) for a *signature* convention that **every `Role.run` override must satisfy in lockstep** — now covered by the new accept-signature AST assertion (every `ROLE_REGISTRY` role's `run` must ACCEPT `client_factory`) plus the positive full-topological-chain run test. The plan chose this on safety grounds (explicit-arg-first, no optimized-build assert hole), but it now imposes a `client_factory` **signature contract on the entire Role hierarchy, including the non-LLM roles** (`reporter`/`reflector`/`memorist`/`seed_xbow`) that accept-and-ignore it. This contract is enforced by test, not merely by convention.
- `approve` changes from terminal to scheduling a live pentest (Improvement 4), promoting `approval_flags` to load-bearing tier gates on Path B.
- Once `osa_multi_provider_llm` is ON, both a fresh-plan default engine run **and** interview/chat fail-closed with `CredentialNotFound` when no per-user Anthropic credential exists (intended, surfaced by the pre-create auth popup).
- Per-invocation resolution issues a fresh DB credential lookup per role call (accepted cost for immediate revocation + audit fidelity).

**Follow-ups.**
- OAuth credential flow when client IDs are configured (API-key only today).
- Monitor per-invocation resolution latency; if it becomes hot, introduce a **single-turn-scoped** cache (never session-scoped) preserving the revocation contract.
- Consider extending the disjoint-namespace invariant to a startup assertion, not just a test.
