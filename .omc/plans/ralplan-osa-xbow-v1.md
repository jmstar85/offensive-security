### Decision Drivers

- **D1 — Safety-chain bit-for-bit preservation is the hardest v1.1 constraint.** [`filter_plan_steps`](backend/app/safety/plan_filter.py) + `filter_by_tier_flags` + `RiskFilter` + `WhitelistShim` + `KaliBackend` hardening + docker-socket-proxy + image-regex middleware + `audit_kali.*` events MUST all fire on every new agent path with zero regression. Rules out wholesale replacement; forces Coordinator as façade hooked AFTER Layer-1 whitelist AND BEFORE planner pipeline. Fresh-plan lane (`session.plan_json IS NULL`) runs Coordinator. Saved-workflow lane defaults to SKIPPED but operators may opt-in via `Workflow.skip_coordinator_replay=false` + `osa_coordinator_replay_enabled=true` (MF-CRITIC-1 resolved v1.1) — opt-in path emits `coordinator.replay_drift_detected` audit and NEVER mutates saved `plan_json` so byte-identical regression on default flags is preserved.
- **D2 — User-mandated reuse-first economics.** 13 existing slugs cover all of Discovery + much of Attack; digest-pinned `osa-kali` is the canonical Attack Machine; Performer + 6-role substrate is already an agent runtime. Cheapest XBOW-shaped path: three Pentester subclasses with narrowed `tools_allowed` slices + new vectors as `KaliWhitelistShim` arg profiles INSIDE `osa-kali` (zero new attack containers), with only 3 net-new sidecars (mitmproxy, headless-browser, interactsh) each closing a specific XBOW box gap and each with documented reuse-first rejection rationale. Interactsh network-isolated per A3.4 BIDIRECTIONAL membership invariant.
- **D3 — Live operator monitoring of inter-agent conversation is product-defining (XBOW Box 14).** Existing `event_bus` + `/api/v1/ws/sessions/{id}` + `TwoPaneShell` + `?topics=` filter + `MsgChain` persistence already provide substrate; only new `conversation` topic + Conversation tab + `Performer.run_session` publishing Role-turn messages + asymmetric-defense scrubber are needed — no new transport, no polling, no new infra. Separate `raw_conversation` topic (A7.4) provides team-admin-only triage so operators are never tempted to disable the scrubber.
- **D4 — Multi-LLM with per-user credentials is non-negotiable.** Drives `ModelClient` → `LLMClient` generalisation behind existing `Response` dataclass + new `user_llm_credentials` table with Fernet at-rest encryption + OAuth callback handlers + per-provider token/cost counters with TWO-LAYER PRE-EMPTIVE session budget guard (A4.2) — Layer-A before `asyncio.gather()` spawns, Layer-B inside each gathered task. Request-scoped contextvars (A4.4) is the chosen credential-propagation mechanism, validated by W0.5 load harness (SF1).
- **D5 — Risk-bounded rollout via CI-invariants-first wave ordering.** Wave 0 (CI scaffolding) + Wave 0.5 (load harness + property-based fuzz) lands BEFORE every other wave so the highest-blast-radius surface (credential vault in W1) merges under gates that catch it. W1 → W2a → W2b → W3 → W4 → W5. Each wave's production flag tuple is one of 4 supported topologies (A8.4); non-production fuzz testing of unsupported combinations gated to W0.

### Invalidation rationale

- **multi_agent_refactor — rejected as spine but partially adopted.** Its `AgentThread` + `AgentExecution` two-model split adds conceptual overhead vs `incremental_addon`'s single `AgentFamilyInstance` row; doesn't address saved-workflow contradiction with cleanest resolution; executor→rescope gap closure not test-gated.
- **overhaul_xbow_clone — rejected.** Risk=4 + Effort=5 with 4-6 engineer-weeks materially exceeds PR-sized phases constraint; adds Redis as new failure axis beyond three justified sidecars; builds parallel `FlowPageV2` + four new sidebar entries while keeping legacy `FlowPage` mounted, creating two concurrent UI surfaces with deferred deprecation; weaker reuse posture (introduces `AgentBus` + `FamilySpawner` + `AgentInstance` abstractions where Performer + 6-role substrate already provides spawning runtime); per-provider cost-drift risk flagged but no pre-emptive budget guard committed to PR1.

## ADR — Architecture Decision Record

### Decision

Adopt the **incremental_addon** option as the spine of OSA v2.0, layering an XBOW-shaped Coordinator + three Pentester-subclass agent families + multi-LLM with per-user credentials + three justified sidecars (mitmproxy / headless-browser / interactsh) onto the existing v1.1 `OrchestratorService` + `Performer` + 13-slug catalog. New attack vectors land as `KaliWhitelistShim` arg profiles INSIDE the digest-pinned `osa-kali` image. Rollout is CI-invariants-first across 8 waves (W0 → W0.5 → W1 → W2a → W2b → W3 → W4 → W5) with bundled flag tuples in production (T1/T2/T3/T4) and per-flag toggling in non-production. **The decision is conditional on resolving 9 MUST-FIX items from the critic verdict (see Follow-ups).**

### Drivers

- **D1** Safety-chain bit-for-bit preservation (the hardest v1.1 constraint).
- **D2** User-mandated reuse-first economics (13 existing slugs + osa-kali + 6-role substrate).
- **D3** Live operator monitoring of inter-agent conversation as product-defining (XBOW Box 14).
- **D4** Multi-LLM with per-user credentials as non-negotiable product requirement.
- **D5** Risk-bounded rollout via CI-invariants-first wave ordering.

### Alternatives Considered

- **multi_agent_refactor** — Medium-rebuild with 3 explicit waves + AST/compose-lint CI invariants. Cherry-picks adopted: 3-wave PR sequencing, CI invariants list, surfacing open design questions in PR descriptions, Live Agents tab separation. Rejected as standalone for `AgentThread`+`AgentExecution` two-model overhead vs single `AgentFamilyInstance` row.
- **overhaul_xbow_clone** — Maximum-fidelity XBOW clone with Redis-backed inter-agent bus, four-pane `FlowPageV2`, full credential vault. Cherry-picks adopted: safety preservation proof sketch as PR-description artifact, `OSA_TRAFFIC_VIA_MITM` Attack-family-only default, `ApproveDialog` explicit checkboxes, self-hosted interactsh with `OSA_INTERACTSH_DOMAIN`, network-isolation invariant for `osa-interactsh` (revised into A3.4 bidirectional). Rejected as standalone for Risk=4 + Effort=5 exceeding PR-sized phases; Redis as net-new failure axis; concurrent `FlowPage` + `FlowPageV2` surfaces.

### Why Chosen

`incremental_addon` is the option with the **strongest reuse posture** (zero net-new attack containers, three sidecars each with documented XBOW-box-gap rationale + reuse-first rejection rationale per SF5) AND the **safety-additive-only invariant** (filter chain + audit schemas + AST gates extend, not replace). Saved-workflow lane covered by the unconditional Coordinator skip + regression test asserting Coordinator never runs on replay (MF1 — **pending MF-CRITIC-1 reopen to opt-out variant**). `ROLE_TOPOLOGICAL_ORDER` fallback preserved via seed.py + seed_xbow.py split that never appears in `sys.modules` in off-state (MF5). Interactsh isolation converted to bidirectional membership invariant with runtime assertion (MF6 — **pending MF-CRITIC-3 docker-socket-proxy contradiction resolution**). Single Alembic head with three additive tables.

### Consequences

- **Positive:** byte-identical v1.1 replay (T1) preserved by W0-pinned comparator; CI invariants gate every merge; CODEOWNERS covers all new safety surfaces; three justified sidecars with documented rejection rationale for alternatives; per-user credential isolation empirically enforced under load (pending PR0.0 spike per MF-CRITIC-2); two-layer pre-emptive budget guard prevents fanout overshoot (pending SF-CRITIC-2 calibration).
- **Negative / open:** ~40 net-new Python modules belies the "incremental" framing (MF-CRITIC-6: re-rate to Risk=4 Effort=6 OR retire scope via S2); concurrency model (`asyncio.gather` + `contextvars.copy_context`) does not exist in `performer.py` today (MF-CRITIC-2 spike required); A7.4 `raw_conversation` and SF4 access control gate on `team-admin` role that does not exist in `UserRole` enum (MF-CRITIC-4 must resolve); L2 entropy + L4 circuit-breaker risk unusable steady state without measured FPR (MF-CRITIC-5); A3.4 runtime assertion mechanism contradicts A6.3 docker-socket-proxy denylist (MF-CRITIC-3 must pick one); A8.4 bundled tuples in prod + independent in dev makes prod incidents non-reproducible in dev (MF-CRITIC-8: replace with pairwise prereq matrix); A8.2 unconditional Coordinator-skip-on-replay forecloses the "fully autonomous platform" product goal for saved workflows (MF-CRITIC-1: replace with operator opt-out).
